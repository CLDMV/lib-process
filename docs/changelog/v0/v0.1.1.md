# `@cldmv/lib-process` v0.1.1 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `next` → `master`

---

## Overview

A lock is now free the moment `release()` returns. Before, a process that released a lock and then blocked, for example on a `spawnSync` of the next process that wants the same lock, left that process waiting on an internal mutex until it failed with `ERR_LIB_PROCESS_MUTEX_TIMEOUT` after 10 seconds. The same applies to a holder's `close()`.

The CommonJS entry is now the generic shim shared by the CLDMV libraries, with `require()` returning the same module object as before. The rest is CI and dev-tooling housekeeping.

## 🐛 Bug Fixes

### `release()` and `close()` free the folder before they return ([#15](https://github.com/CLDMV/lib-process/pull/15), fixes [#6](https://github.com/CLDMV/lib-process/issues/6))

`release()` and `close()` took the short cross-process mutex that serializes takeovers before they returned. The mutex is an abstract socket, which binds synchronously, and it was only let go once the event loop ran again. A caller that released without waiting and then blocked kept the mutex bound, so the next process timed out on it.

Now `close()` stops listening first, synchronously, so the folder is free as soon as `release()` or `close()` returns, even if the caller then blocks. The socket file is cleaned up afterwards under the mutex. Another process can take the folder over before that cleanup runs, and its socket often gets the same inode number, so the cleanup decides by liveness instead: it only removes the file when nothing answers on it, and a newer holder's live socket is never touched ([#17](https://github.com/CLDMV/lib-process/pull/17)). A probe that reaches a listener just as it closes now counts as dead (`ECONNRESET`) instead of throwing `ERR_LIB_PROCESS_UNKNOWN_STATE`.

The returned promise still settles once the cleanup is done, so `await held.release()` behaves as before. New tests release without waiting, `spawnSync` a child that takes the same folder, and expect it to get the folder at once, and hold the cleanup back until another holder has taken over to check the newer socket survives; the multi-process mutual-exclusion test still holds.

## 📦 Packaging

### The CommonJS entry is the generic shim ([#12](https://github.com/CLDMV/lib-process/pull/12))

`src/index.cjs`, published as `dist/index.cjs`, is now the shim every CLDMV library ships: a Node.js version guard, then `require("./index.mjs")`. lib-process exports several values, so `require("@cldmv/lib-process")` returns the module object, exactly as before. The CJS test checks its keys and values against the ESM entry in `src/` and `dist/`.

## Upgrade notes

- No breaking changes. Code that awaits `release()` or `close()` behaves as in [v0.1.0](./v0.1.0.md); code that doesn't await them now frees the lock straight away instead of holding up the next process.
