# lib-process v0.1.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `release/0.1.0`

---

## Overview

First release. lib-process replaces pid files and bare `process.kill()` with three small tools: a liveness check that a crash can't leave stale, an exclusive lock that is released the moment its holder dies, and a kill that only reaches the caller's own processes.

`lock()` and `safeKill()` are Linux only in this release. `alive` works on Linux and macOS; on Windows `alive.check()` always says `"unknown"`.

---

## ✨ Features

### `alive.hold()` / `alive.check()` ([#2](https://github.com/CLDMV/lib-process/pull/2))

The holder listens on `alive.sock` inside a folder. Connecting tells anyone else whether it's still running: a successful connect means alive, a refused connect means dead (even when a crash or SIGKILL left the socket file behind), and no socket means unknown, so the caller can fall back to the folder's age. It works across PID namespaces, because the socket is a file. Socket paths are limited to 107 bytes on Linux (103 on macOS), and longer paths throw `ERR_LIB_PROCESS_PATH_TOO_LONG`.

### `lock()` ([#2](https://github.com/CLDMV/lib-process/pull/2))

An exclusive lock built on `alive`. A dead holder's lock is taken over at once, with no stale timeout to wait out. Takeovers run under a short mutex held as a listening socket in Linux's abstract namespace, which the kernel frees when its process dies, so two contenders never both win and a crash can't leave the mutex stuck. `wait` and `retryInterval` control how long it keeps trying while a live holder has it.

### `safeKill()` ([#2](https://github.com/CLDMV/lib-process/pull/2))

Signals a list of pids and skips every one it can't prove is safe, with a reason for each. It never signals pid 0, pid 1, negative or group ids, the caller, its ancestors or a thread id. It signals the caller's descendants, and with `reported: { since }` also processes that started at or after `since`. It reads each process's start time again right before the signal, so a reused pid isn't hit, and it refuses to run when `/proc` belongs to another PID namespace.

## 🔧 CI & tooling

- The v4 workflow set, the tsup build into `dist/` with a thin CommonJS wrapper, and tests through `@cldmv/vitest-runner` with 100% coverage required ([#2](https://github.com/CLDMV/lib-process/pull/2)).
- Tests that fork processes or send real signals only run inside a PID namespace (`LIB_PROCESS_TEST_NAMESPACE=1` and a pid 1 that isn't a host init), so they're skipped on GitHub runners.
